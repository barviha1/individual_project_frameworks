# HRDocs – система управления кадровыми документами

## Назначение

HRDocs – приложение для учёта сотрудников, кадровых документов и контроля
сроков их действия. Консольная версия приложения (ПР3) дополнена
веб-интерфейсом на Django (ПР5).

Приложение позволяет:
* просматривать сотрудников в браузере;
* просматривать карточку сотрудника и его документы;
* просматривать список документов с цветными статусами срока действия;
* просматривать карточку документа со связанными сотрудником и категорией;
* просматривать категории документов и число документов в каждой;
* видеть статистику документов по статусам (активен / скоро истекает / истёк);
* добавлять, редактировать и удалять сотрудников и категории (консоль);
* добавлять документы и искать их по сотруднику и категории (консоль);
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;
* CSS и Bootstrap 5.3 – оформление страниц (подключается через CDN);
* pytest – автоматизированные тесты;
* flake8 – проверка качества кода.

## Целевая аудитория

* HR-специалисты и сотрудники отдела кадров;
* руководители подразделений;
* сотрудники организации – для просмотра статуса своих документов
  (в перспективе).

## Предметная область

Основными объектами предметной области являются:
* сотрудник;
* категория документа;
* документ.

Сотрудник может иметь несколько документов. Каждый документ относится к одной
категории и связан ровно с одним сотрудником. Для документа определяется срок
действия, по которому вычисляется статус: «Активен», «Скоро истекает»
(осталось не более 30 дней) или «Истёк».

## Основные сущности

### Employee – сотрудник

Атрибуты: `id`, `name`, `position`, `department`, `hire_date`.

Основные методы:
* `get_seniority()` – расчёт стажа сотрудника в годах;
* `update_info()` – изменение должности и/или отдела;
* `from_data()` – создание объекта из набора данных JSON;
* `__str__()` – строковое представление сотрудника.

### Category – категория документа

Атрибуты: `name`, `description`.

Основные методы:
* `update_description()` – изменение описания категории;
* `validate_name()` – проверка, что название не пустое (`@staticmethod`);
* `from_data()` – создание объекта из набора данных JSON (`@classmethod`);
* `__str__()` – строковое представление категории.

### Document – документ

Атрибуты: `id`, `name`, `category` (объект `Category`), `employee` (объект
`Employee`), `expiry_date`.

Основные методы:
* `get_status()` – статус срока действия на заданную дату;
* `to_report_line()` – строка отчёта по документу;
* `__str__()` – строковое представление документа.

## Страницы веб-интерфейса

* `/` – главная страница: описание приложения и навигация
  (view-функция `index()`);
* `/employees/` – список сотрудников из `data/employees.json`
  (view-функция `employees()`);
* `/employees/<int:employee_id>/` – карточка сотрудника и его документы
  (view-функция `employee_detail()`);
* `/categories/` – список категорий и число документов в каждой
  (view-функция `categories()`);
* `/documents/` – список документов, упорядоченный по сроку действия, со
  статистикой по статусам (view-функция `documents()`);
* `/documents/<int:document_id>/` – карточка документа со связанными
  сотрудником и категорией (view-функция `document_detail()`).

Если сотрудник или документ с указанным идентификатором не найден,
соответствующая страница возвращает код статуса 404.

Для адресов, которым не нашлось маршрута (несуществующий URL или значение, не
подошедшее под конвертер `<int:...>`, например `/employees/abc/`), настроен
обработчик `handler404` (корневой `hrdocs/urls.py`): вместо служебной страницы
Django показывается страница проекта «404 – страница не найдена» с кнопкой
возврата на главную. Обработчик действует при `DEBUG = False`; при
`DEBUG = True` Django показывает техническую страницу отладки.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка сотрудников и карточки сотрудника;
* просмотр документов сотрудника;
* просмотр списка документов и карточки документа;
* определение статуса срока действия документа на текущую дату;
* статистика документов по статусам;
* просмотр списка категорий.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии. В веб-интерфейсе
они появятся, когда будут добавлены формы и POST-запросы:

* добавление, редактирование и удаление сотрудника;
* поиск сотрудника по имени;
* создание, редактирование и удаление категории;
* создание документа;
* поиск документов по сотруднику и по категории (по выбору пользователя).

## Хранение данных

Данные приложения хранятся в JSON-файлах:
* `data/employees.json`;
* `data/categories.json`;
* `data/documents.json`.

При загрузке данные из JSON преобразуются в объекты `Employee`, `Category` и
`Document`. При сохранении объекты преобразуются в данные JSON. Для связи
документа с сотрудником и категорией в `documents.json` используются
`employee_id` и название категории `category`.

## Django-приложения

| Область | Приложение | Почему |
|---|---|---|
| Главная страница | `homepage` | Точка входа в систему, не относится к другим областям |
| Сотрудники | `employees` | Отдельная сущность `Employee` из ПР3 |
| Категории | `categories` | Отдельная сущность `Category` из ПР3 |
| Документы | `documents` | Отдельная сущность `Document` из ПР3 |

Сотрудник кадровой системы – это учётная запись о человеке, а не пользователь,
входящий в систему, поэтому встроенная модель `User` Django (`django.contrib.auth`)
для него не используется. Аутентификация будет рассмотрена в следующих темах.

Файл `models.py` каждого Django-приложения пока пуст и не связан с пакетом
`models/` проекта: пакет `models/` содержит классы предметной области ПР3, а
Django-модели будут созданы на следующих практических работах.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3): запуск, меню, ввод данных,
пользовательские сценарии.

### `hrdocs/`

Пакет настроек Django-проекта:
* `settings.py` – настройки проекта (приложения, язык `ru-RU`, часовой пояс
  `Europe/Moscow`, `DEBUG`, `ALLOWED_HOSTS`);
* `urls.py` – маршрутизация верхнего уровня (`include()` приложений) и
  обработчик ошибки 404 (`handler404`);
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`

Django-приложение главной страницы:
* `views.py` – функция `page()` (общий HTML-каркас), `status_badge()`
  (цветной бейдж статуса), view-функция `index()` и обработчик ошибки 404
  `page_not_found()`;
* `urls.py` – маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт общий вид
всех остальных страниц. Остальные приложения импортируют её.

### `employees/`, `categories/`, `documents/`

Django-приложения соответствующих сущностей:
* `views.py` – view-функции страниц;
* `urls.py` – маршруты приложения;
* `tests.py` – тесты страниц;
* `models.py` – Django-модели (заполняется в следующих работах).

### `models/`

Классы предметной области и функции работы с ними (пакет ПР3):
* `employees.py` – класс `Employee` и функции работы с сотрудниками;
* `categories.py` – класс `Category` и функции работы с категориями;
* `documents.py` – класс `Document` и функции работы с документами.

### `storage.py`

Загрузка и сохранение данных: JSON → объекты Python и объекты Python → JSON.
Функция `load_all()` загружает все коллекции для веб-интерфейса; путь к каталогу
`data/` определяется относительно самого файла и не зависит от того, откуда
запущен сервер.

### `utils.py`

Вспомогательные функции консольного ввода: `input_int()`, `input_date()`,
`input_nonempty()`, `input_optional()`.

### `tests/`

Автоматизированные тесты предметной модели (pytest).

## Запуск приложения

Подготовка окружения (один раз):

```text
python3 -m venv venv
source venv/bin/activate        # macOS / Linux
venv\Scripts\activate           # Windows
pip install -r requirements.txt
python manage.py migrate
```

Веб-версия (Django):

```text
python manage.py runserver
```

После запуска открыть в браузере адрес:

```text
http://127.0.0.1:8000/
```

Консольная версия (сохранена):

```text
python main.py
```
