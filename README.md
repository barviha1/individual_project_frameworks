# HRDocs – система управления кадровыми документами

## Назначение

HRDocs – приложение для учёта сотрудников, кадровых документов и контроля
сроков их действия. Консольная версия приложения (ПР3) дополнена
веб-интерфейсом на Django (ПР5), который в ПР6 переведён на систему шаблонов
Django (Django Template Language).

Приложение позволяет:
* просматривать сотрудников в браузере;
* просматривать карточку сотрудника и его документы;
* просматривать список документов с цветными статусами срока действия;
* просматривать карточку документа со связанными сотрудником и категорией;
* просматривать категории документов и число документов в каждой;
* видеть статистику документов по статусам (активен / скоро истекает / истёк);
* добавлять, редактировать и удалять сотрудников и категории (консоль);
* добавлять документы и искать их по сотруднику и категории (консоль);
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;
* Django 5.2 – веб-фреймворк;
* Django Template Language (DTL) – шаблоны веб-страниц;
* HTML5 – разметка веб-страниц;
* CSS3 – собственные стили проекта и Bootstrap 5.3 (подключается через CDN);
* JavaScript – небольшое клиентское поведение интерфейса;
* JSON – хранение данных;
* pytest – автоматизированные тесты;
* flake8 – проверка качества кода.

## Целевая аудитория

* HR-специалисты и сотрудники отдела кадров;
* руководители подразделений;
* сотрудники организации – для просмотра статуса своих документов
  (в перспективе).

## Предметная область

Основными объектами предметной области являются:
* сотрудник;
* категория документа;
* документ.

Сотрудник может иметь несколько документов. Каждый документ относится к одной
категории и связан ровно с одним сотрудником. Для документа определяется срок
действия, по которому вычисляется статус: «Активен», «Скоро истекает»
(осталось не более 30 дней) или «Истёк».

## Основные сущности

### Employee – сотрудник

Атрибуты: `id`, `name`, `position`, `department`, `hire_date`.

Основные методы:
* `get_seniority()` – расчёт стажа сотрудника в годах;
* `update_info()` – изменение должности и/или отдела;
* `from_data()` – создание объекта из набора данных JSON;
* `__str__()` – строковое представление сотрудника.

### Category – категория документа

Атрибуты: `name`, `description`.

Основные методы:
* `update_description()` – изменение описания категории;
* `validate_name()` – проверка, что название не пустое (`@staticmethod`);
* `from_data()` – создание объекта из набора данных JSON (`@classmethod`);
* `__str__()` – строковое представление категории.

### Document – документ

Атрибуты: `id`, `name`, `category` (объект `Category`), `employee` (объект
`Employee`), `expiry_date`.

Основные методы:
* `get_status()` – статус срока действия на заданную дату;
* `to_report_line()` – строка отчёта по документу;
* `__str__()` – строковое представление документа.

## Страницы веб-интерфейса

* `/` – главная страница: описание приложения и навигация
  (view-функция `index()`);
* `/employees/` – список сотрудников из `data/employees.json`
  (view-функция `employees()`);
* `/employees/<int:employee_id>/` – карточка сотрудника и его документы
  (view-функция `employee_detail()`);
* `/categories/` – список категорий и число документов в каждой
  (view-функция `categories()`);
* `/documents/` – список документов, упорядоченный по сроку действия, со
  статистикой по статусам (view-функция `documents()`);
* `/documents/<int:document_id>/` – карточка документа со связанными
  сотрудником и категорией (view-функция `document_detail()`).

Если сотрудник или документ с указанным идентификатором не найден,
соответствующая страница возвращает код статуса 404.

Все страницы формируются Django-шаблонами: view-функция получает данные,
передаёт их в шаблон через контекст и вызывает `render()`. Генерация HTML
в Python-коде веб-представлений не используется; функция `page()` из ПР5
удалена.

Для адресов, которым не нашлось маршрута (несуществующий URL или значение, не
подошедшее под конвертер `<int:...>`, например `/employees/abc/`), настроен
обработчик `handler404` (корневой `hrdocs/urls.py`): вместо служебной страницы
Django показывается страница проекта «404 – страница не найдена» с кнопкой
возврата на главную. Обработчик действует при `DEBUG = False`; при
`DEBUG = True` Django показывает техническую страницу отладки. Страница 404
строится из шаблона `homepage/templates/homepage/404.html`.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка сотрудников и карточки сотрудника;
* просмотр документов сотрудника;
* просмотр списка документов и карточки документа;
* определение статуса срока действия документа на текущую дату;
* статистика документов по статусам;
* просмотр списка категорий.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии. В веб-интерфейсе
они появятся, когда будут добавлены формы и POST-запросы:

* добавление, редактирование и удаление сотрудника;
* поиск сотрудника по имени;
* создание, редактирование и удаление категории;
* создание документа;
* поиск документов по сотруднику и по категории (по выбору пользователя).

## Хранение данных

Данные приложения хранятся в JSON-файлах:
* `data/employees.json`;
* `data/categories.json`;
* `data/documents.json`.

При загрузке данные из JSON преобразуются в объекты `Employee`, `Category` и
`Document`. При сохранении объекты преобразуются в данные JSON. Для связи
документа с сотрудником и категорией в `documents.json` используются
`employee_id` и название категории `category`.

## Django-приложения

| Область | Приложение | Почему |
|---|---|---|
| Главная страница | `homepage` | Точка входа в систему, не относится к другим областям |
| Сотрудники | `employees` | Отдельная сущность `Employee` из ПР3 |
| Категории | `categories` | Отдельная сущность `Category` из ПР3 |
| Документы | `documents` | Отдельная сущность `Document` из ПР3 |

Сотрудник кадровой системы – это учётная запись о человеке, а не пользователь,
входящий в систему, поэтому встроенная модель `User` Django (`django.contrib.auth`)
для него не используется. Аутентификация будет рассмотрена в следующих темах.

Файл `models.py` каждого Django-приложения пока пуст и не связан с пакетом
`models/` проекта: пакет `models/` содержит классы предметной области ПР3, а
Django-модели будут созданы на следующих практических работах.

## Django Template Language

Веб-часть проекта построена по схеме:

```text
JSON → объекты Python → view → контекст → шаблон Django → HTML → HTTP-ответ
```

View-функция подготавливает данные и не формирует HTML. Шаблон отвечает только
за представление данных.

### Базовый шаблон и наследование

Общая структура всех страниц находится в `templates/base.html`: объявление
документа, кодировка, заголовок, подключение Bootstrap и собственного CSS,
шапка с логотипом и навигацией, основной контейнер, подвал и подключение
JavaScript. Каталог `templates/` указан в параметре `DIRS` списка `TEMPLATES`
файла `settings.py`.

Дочерние шаблоны наследуют базовый и переопределяют блоки:

```text
{% extends "base.html" %}
{% block title %}Сотрудники – HRDocs{% endblock %}
{% block content %} ... {% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные файлы и подключаются через
`{% include %}`:

* `templates/includes/navigation.html` – навигация сайта (подключается в
  `base.html`);
* `employees/includes/employee_card.html` – карточка одного сотрудника;
* `documents/includes/document_status.html` – цветной бейдж статуса документа
  (используется в списке документов, на странице документа и в карточке
  сотрудника).

### Контекст

View-функции передают данные в шаблон словарём контекста, например:

```text
context = {"employee_rows": [...]}
return render(request, "employees/employee_list.html", context)
```

Методы объектов, которым нужен аргумент (`get_seniority(today)`,
`get_status(today)`), вызываются во view: результат передаётся в шаблон вместе
с объектом. Предметная логика остаётся в Python-коде и классах из `models/`.

### Циклы и условия

* `{% for ... %}` с веткой `{% empty %}` – списки сотрудников, документов и
  категорий, сообщение при отсутствии данных;
* `{% if %}` / `{% elif %}` / `{% else %}` – статус документа, а также
  отображение страницы найденного или ненайденного сотрудника и документа.

Для несуществующего сотрудника или документа во view в шаблон передаётся
`None`, шаблон выводит сообщение, а ответ получает код 404
(`status=404 if ... is None else 200`).

## Фильтры шаблонов

В шаблонах используются стандартные фильтры DTL:

* `{{ employee_rows|length }}` – число сотрудников (аналогично документы и
  категории);
* `{{ employee.name|default:"Без имени" }}` – значение по умолчанию;
* `{{ row.expiry|date:"d.m.Y" }}` – формат даты (дата приёма и срок действия
  документа во view преобразуются из строки JSON в `date`).

Фильтры используются только для представления данных и не содержат бизнес-логики.

## Именованные URL и пространства имён

У каждого приложения задан `app_name`, у маршрутов – `name`. Ссылки в шаблонах
формируются через `{% url %}`, жёстко заданные адреса не используются:

| Имя маршрута | Адрес |
|---|---|
| `homepage:index` | `/` |
| `employees:list` | `/employees/` |
| `employees:detail` | `/employees/<id>/` |
| `documents:list` | `/documents/` |
| `documents:detail` | `/documents/<id>/` |
| `categories:list` | `/categories/` |

Пример: `{% url 'employees:detail' employee.id %}`.

## Статические файлы

Собственные статические файлы проекта находятся в
`homepage/static/homepage/`:

* `css/style.css` – собственные стили (шапка, карточка сотрудника
  `.employee-card`, статус документа `.document-status`, подвал);
* `js/main.js` – подстановка текущего года в подвал;
* `img/logo.png` – логотип HRDocs.

В `base.html` первой строкой указано `{% load static %}`, файлы подключаются
через `{% static 'homepage/css/style.css' %}` и аналогично для JS и логотипа.
Bootstrap сохранён для базовой вёрстки и не заменяет собственный CSS.

Проверить поиск статического файла можно командой:

```text
python manage.py findstatic homepage/img/logo.png
```

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3): запуск, меню, ввод данных,
пользовательские сценарии.

### `hrdocs/`

Пакет настроек Django-проекта:
* `settings.py` – настройки проекта (приложения, язык `ru-RU`, часовой пояс
  `Europe/Moscow`, `DEBUG`, `ALLOWED_HOSTS`, каталог шаблонов `DIRS`);
* `urls.py` – маршрутизация верхнего уровня (`include()` приложений) и
  обработчик ошибки 404 (`handler404`);
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `templates/`

Шаблоны уровня проекта: базовый шаблон `base.html` и подключаемая навигация
`includes/navigation.html`.

### `homepage/`

Django-приложение главной страницы:
* `views.py` – view-функция `index()` и обработчик ошибки 404
  `page_not_found()`, оба используют `render()`;
* `urls.py` – маршрут главной страницы (`app_name = "homepage"`);
* `templates/homepage/` – шаблоны `index.html` и `404.html`;
* `static/homepage/` – собственные CSS, JavaScript и логотип проекта.

### `employees/`, `categories/`, `documents/`

Django-приложения соответствующих сущностей:
* `views.py` – view-функции страниц (получают данные, передают контекст в
  шаблон, вызывают `render()`);
* `urls.py` – маршруты приложения с пространством имён `app_name`;
* `templates/<приложение>/` – шаблоны страниц и включаемые шаблоны;
* `tests.py` – тесты страниц и шаблонов;
* `models.py` – Django-модели (заполняется в следующих работах).

### `models/`

Классы предметной области и функции работы с ними (пакет ПР3):
* `employees.py` – класс `Employee` и функции работы с сотрудниками;
* `categories.py` – класс `Category` и функции работы с категориями;
* `documents.py` – класс `Document` и функции работы с документами.

### `storage.py`

Загрузка и сохранение данных: JSON → объекты Python и объекты Python → JSON.
Функция `load_all()` загружает все коллекции для веб-интерфейса; путь к каталогу
`data/` определяется относительно самого файла и не зависит от того, откуда
запущен сервер.

### `utils.py`

Вспомогательные функции консольного ввода: `input_int()`, `input_date()`,
`input_nonempty()`, `input_optional()`.

### `tests/`

Автоматизированные тесты предметной модели (pytest).

### Веб-слой (ПР5–ПР6)

| Приложение | Функция | Файл | Назначение |
|---|---|---|---|
| `homepage` | `index()` | `homepage/views.py` | главная страница `/`, шаблон `homepage/index.html` |
| `homepage` | `page_not_found()` | `homepage/views.py` | обработчик `handler404`: шаблон `homepage/404.html`, код статуса 404 |
| `employees` | `employees()` | `employees/views.py` | страница `/employees/`, шаблон `employees/employee_list.html` |
| `employees` | `employee_detail()` | `employees/views.py` | страница `/employees/<int:employee_id>/`; 404, если не найден |
| `categories` | `categories()` | `categories/views.py` | страница `/categories/`, шаблон `categories/category_list.html` |
| `documents` | `documents()` | `documents/views.py` | страница `/documents/`, шаблон `documents/document_list.html` |
| `documents` | `document_detail()` | `documents/views.py` | страница `/documents/<int:document_id>/`; 404, если не найден |
| `documents` | `build_document_rows()` | `documents/views.py` | подготовка данных документов для шаблона: статус и дата окончания |

Функция `page()` из ПР5 удалена: общий каркас страниц теперь задаёт шаблон
`templates/base.html`, а цветной бейдж статуса – включаемый шаблон
`documents/includes/document_status.html`.

Функции сущностей и хранилища используются одновременно консольной и
веб-версией приложения: view-функции вызывают `load_all()`,
`find_employee_by_id()`, `find_document_by_id()` и методы объектов вместо
консольных сценариев `main.py`. Предметная область ПР3 сохраняется в
веб-интерфейсе.
