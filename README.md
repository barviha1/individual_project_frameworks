# Система управления кадровыми документами

Консольное приложение для учёта сотрудников, кадровых документов
и контроля сроков их действия.

## Назначение

Приложение автоматизирует учёт и хранение кадровых документов сотрудников
организации: централизованное хранение документов (трудовых договоров,
приказов, справок и т.п.), их классификацию по категориям и контроль
сроков действия — чтобы кадровая служба могла быстро находить нужный
документ и не пропускала даты, требующие внимания.

## Целевая аудитория

- HR-специалисты и сотрудники отдела кадров;
- руководители подразделений;
- сотрудники организации — для просмотра статуса своих документов
  (в перспективе).

## Предметная область

Кадровое делопроизводство: учёт сотрудников, хранение и систематизация
связанных с ними документов, отслеживание сроков действия документов.
Один сотрудник может иметь несколько документов; каждый документ относится
к одной категории и связан ровно с одним сотрудником.

## Основные сущности (классы)

### Employee — сотрудник

Атрибуты: `id`, `name`, `position`, `department`, `hire_date`.

Методы:
- `get_seniority(today)` — вычислить стаж сотрудника в годах;
- `update_info(position, department)` — изменить должность и/или отдел;
- `from_data(data)` (classmethod) — создать сотрудника из словаря JSON;
- `__str__()` — строковое представление сотрудника.

### Category — категория документа

Атрибуты: `name`, `description`.

Методы:
- `update_description(description)` — изменить описание категории;
- `validate_name(name)` (staticmethod) — проверить, что название не пустое;
- `from_data(data)` (classmethod) — создать категорию из словаря JSON;
- `__str__()` — строковое представление категории.

### Document — документ

Атрибуты: `id`, `name`, `category` (объект `Category`), `employee`
(объект `Employee`), `expiry_date`.

Методы:
- `get_status(today)` — статус срока действия: активен / скоро истекает /
  истёк;
- `to_report_line(status)` — строка отчёта по документу;
- `__str__()` — строковое представление документа.

## Взаимодействие объектов

`Document` хранит прямые ссылки на объекты `Employee` и `Category`,
а не только их идентификаторы:

```
Document
├── employee → Employee
└── category → Category
```

Это позволяет обращаться к данным связанных объектов напрямую:
`document.employee.name`, `document.category.description`. В JSON-файлах
при этом сохраняются только идентификаторы (`employee_id`, `category`
как название) — связи восстанавливаются при загрузке.

## Возможности

- добавление, поиск, редактирование и удаление сотрудников;
- добавление документов с привязкой к сотруднику и категории;
- создание, редактирование и удаление категорий документов;
- отслеживание сроков действия документов и определение статуса;
- поиск и фильтрация документов по сотруднику и по категории;
- статистика по документам и список документов с истекающим сроком;
- сохранение и загрузка всех данных в JSON-файлах с восстановлением
  связей между объектами;
- обработка некорректного ввода и ошибок при работе с файлами данных.

## Формат хранения данных

- `employees.json` — список сотрудников;
- `categories.json` — список категорий (название и описание);
- `documents.json` — список документов; для связи с сотрудником и
  категорией хранятся `employee_id` и название категории, а не сами
  объекты.

## Требования

- Python 3.x;
- pytest;
- flake8.

Установка зависимостей:

```
pip install -r requirements.txt
```

## Запуск программы

```
python main.py
```

## Запуск тестов

```
pytest
```

Тесты проверяют создание и атрибуты объектов `Employee`, `Category` и
`Document`, их методы (`get_seniority`, `get_status`, `to_report_line`,
`validate_name` и др.), а также функции поиска, фильтрации, сортировки
и статистики по коллекциям объектов.
